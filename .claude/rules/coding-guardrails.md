# Coding guardrails

- **Think before coding.** Read the code a change touches and state your assumptions. If a request has two readings, ask instead of picking one silently.
- **Simplicity first.** Write the minimum code that solves the problem. Add no options, abstractions or "for later" code. Deleting code beats adding it.
- **Surgical changes.** Touch only what the request needs. Clean up the orphans your own change creates. Mention unrelated problems; do not fix them silently.
- **Goal-driven execution.** Decide how you will prove the change works, then run that check. Report what you ran and what you skipped.
